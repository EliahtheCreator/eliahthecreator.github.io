# 多语言本地化口语测评 Bot Skill

## 适用场景

当你需要为某个语种的本地化实习生设计口语测评网页 Bot 时使用本 Skill。

适合语种：

- 西班牙语
- 葡萄牙语
- 法语
- 德语
- 日语
- 其他可由浏览器语音识别支持的语言

## 使用前确认

向用户确认：

- 目标语言：`{LANGUAGE}`
- 语音代码：`{LANG_CODE}`，例如 `es-ES`、`pt-BR`、`fr-FR`
- 目标市场：`{MARKET}`
- 测评产品：`{PRODUCT}`

## 测评定位

测评对象是本地化实习生候选人，不按专业翻译标准考核。

重点考察：

- 基础语言能力
- 本地化表达意识
- 目标市场基础认知
- 岗位匹配度

## 固定 5 轮考核

| 轮次 | 类型 | 时长 | 作答语言 | 考察点 |
|---|---|---:|---|---|
| 1 | 基础自我介绍 | 120 秒 | 目标语言 | 发音流利度、基础语法 |
| 2 | 产品出海情景题 | 120 秒 | 目标语言 | 语言表达和本地化产品思维 |
| 3 | 文化与市场认知 | 120 秒 | 目标语言 | 基础市场感知 |
| 4 | 文案改错 | 120 秒 | 目标语言 | 地道表达和 UI 文案习惯 |
| 5 | 开放问答 | 120 秒 | 目标语言 | 岗位匹配度 |

不要额外加题，不要动态减少轮次。

## 题目模板

### 第 1 轮：基础自我介绍

请候选人用 `{LANGUAGE}` 简要介绍自己，包括姓名、专业，以及为什么对本地化工作感兴趣。

### 第 2 轮：产品出海情景题

假设 `{PRODUCT}` 要进入 `{MARKET}` 市场，请候选人用 `{LANGUAGE}` 向本地普通用户介绍这个产品。

### 第 3 轮：文化与市场认知

请候选人用 `{LANGUAGE}` 说出 2 个 `{MARKET}` 用户的网络习惯、文化禁忌或主流社交平台。

### 第 4 轮：文案改错

给出一句生硬机器翻译的产品 UI 文案，请候选人用 `{LANGUAGE}` 改写为更符合本地用户习惯的表达。

### 第 5 轮：开放问答

请候选人用 `{LANGUAGE}` 回答：为什么你适合做 `{MARKET}` 的产品本地化工作？

## 打分维度

满分 100，合格线默认 60。

- 语言基础能力：40 分
- 本地化文案意识：30 分
- 目标市场基础认知：20 分
- 岗位匹配度：10 分

结论规则：

- 总分 >= 70：推荐进入下一环节
- 60 <= 总分 < 70：谨慎评估
- 总分 < 60：不通过

总分必须等于四项分数之和。

## 防作弊机制

必须实现：

1. 先语音后键盘：输入框初始锁定，候选人必须先语音作答。
2. 修改比例限制：语音识别后允许修改，但修改比例不得超过原文的 40%。
3. 限时作答：每轮 120 秒，到时自动停止。
4. 目标语言检测：非目标语言作答需要重录。
5. 连续 2 次无法用目标语言作答，直接终止并判不通过。
6. 首页不展示具体题目，只展示轮次类型和评分维度。

## 页面功能要求

- 首页：测评说明、目标语种、市场、姓名输入框、开始按钮。
- 测评页：当前轮次、题目、倒计时、麦克风按钮、语音转写框、修改比例提示。
- 点评区：每轮结束给中文点评。
- 报告页：总分、分项得分、优势、短板、结论和招聘参考。
- 支持退出后恢复进度。
- 已完成的候选人不能重复测评。

```markdown

- 目标语言：{LANGUAGE}
- 目标市场：{MARKET}
- 总分：{总分}/100
- 结论：推荐进入下一环节 / 谨慎评估 / 不通过

## 分项得分

- 语言基础能力：{分数}/40
- 本地化文案意识：{分数}/30
- 目标市场基础认知：{分数}/20
- 岗位匹配度：{分数}/10

## 核心优势

- {优势 1}
- {优势 2}

## 暴露短板

- {短板 1}
- {短板 2}

{一句话建议}
```

## 技术提示

- 可使用 Web Speech API 做 TTS 和 ASR。
- 语音识别使用 `SpeechRecognition`，不要同时调用 `getUserMedia` 抢占麦克风。
- 纯前端部署时，可用 `localStorage` 保存进度。
- 如果浏览器不支持语音识别，允许降级为文字输入，但仍保留目标语言检测和修改比例限制。

## 安全边界

- 不公开候选人姓名和测评报告。
- 不把真实候选人作答作为演示数据。
- 如果公开视频演示，使用假姓名和模拟作答。
