# Codex-Doubao 编排式简历评估与录入 Skill

## 适用场景

当你需要批量处理某一类岗位的简历，并希望把“判断”和“执行”拆开时使用本 Skill。

适合场景包括：

- 简历数量较多，需要先提取、再评估、再录入台账。
- 岗位有明确画像，需要判断候选人的研究能力、岗位匹配度和风险点。
- 希望 Codex 负责深度判断，执行工具负责读取附件、整理字段、录入表格。
- 需要先让用户复核评估结果，再进入录入流程。

## 角色分工

- Codex：负责理解简历内容、判断候选人与岗位的匹配度、输出评分和评估报告。
- 执行工具：负责读取简历、提取结构化信息、根据最终名单录入 `{目标台账}`。
- 用户：负责复核评分、结论和最终录入名单。

## 输入材料

使用前准备以下材料：

- `{目标岗位}` 的 JD 或岗位画像。
- 候选人简历文件或简历提取结果。
- `{目标台账}` 的字段说明。
- 是否需要录入的判定规则，例如“备选及以上录入”。

## 核心判断原则

不要只按关键词筛选。先理解岗位真正需要解决的问题，再判断候选人经历是否能迁移。

重点看：

- 候选人是否真的理解相关问题，而不是只堆关键词。
- 项目、论文、实习或工作经历里是否有清晰个人贡献。
- 经历与岗位是直接匹配，还是相邻方向可迁移。
- 是否存在需要进一步确认的风险点。
- 简历是否只体现工具使用，而没有体现方法、判断或 ownership。

## 评分模型

默认满分 10 分，可按岗位调整权重。

- 研究或专业能力：45%
- 岗位匹配度：25%
- 贡献深度：15%
- 教育或经历背景：10%
- 工程或落地能力：5%

分数段：

- 8.1-10.0：强烈推荐
- 7.1-8.0：可考虑
- 6.0-7.0：备选
- 6.0 以下：不推荐

## 两阶段流程

### 第一阶段：提取与评估

1. 让执行工具读取简历，输出结构化候选人信息。
2. Codex 基于岗位画像逐份评估。
3. 每位候选人输出评分、结论、主要依据和待确认风险。
4. 生成评估报告。
5. 将报告交给用户复核。

在用户确认前，不要录入台账。

### 第二阶段：复核与录入

只有用户明确说“确认录入”或“开始录入”后，才进入录入阶段。

录入范围默认：

- 强烈推荐
- 可考虑
- 备选

不录入：

- 不推荐
- 用户明确删除的候选人
- 身份、附件或字段无法匹配的候选人

## 评估报告格式

对每位候选人输出：

```markdown
## 候选人：{姓名或编号}

- 评分：{分数}/10
- 结论：强烈推荐 / 可考虑 / 备选 / 不推荐
- 匹配理由：
  - {理由 1}
  - {理由 2}
- 主要风险：
  - {风险 1}
- 需确认问题：
  - {问题 1}
```

## 录入提示词模板

用户复核并确认后，把最终评估报告提供给执行工具，并发送：

```text
以下是已经由用户复核确认的最终录入名单。请以我提供的最终评估报告为准，只录入结论为“备选”“可考虑”或“强烈推荐”的候选人，不要自行扩展名单，不要重新评分。

请根据评估报告、简历附件和目标台账字段，将候选人录入 {目标台账}。

录入要求：
1. 保留最终复核后的姓名、评分、结论和理由。
2. 不要录入“不推荐”候选人。
3. 录入前核对候选人身份、简历附件和已有记录，避免重复录入。
4. 如果候选人无法匹配、字段缺失、目标表不明确或存在其他阻塞，请先停止并报告问题，不要部分录入。

完成后返回：
1. 成功录入名单；
2. 跳过或失败名单及原因；
3. 去重处理结果；
4. 附件处理结果；
5. 目标台账位置。
```

## 安全边界

- 不公开候选人简历、邮箱、电话、联系方式或评估结论。
- 不把内部台账名称、字段权限和组织空间信息写进公开文档。
- 不让执行工具重新评分或扩大名单。
- 不在用户复核前录入。
- 遇到不确定身份或字段，保持待确认。
